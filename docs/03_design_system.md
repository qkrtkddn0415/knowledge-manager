# 03. Design System

## 0. 목적

Second Brain의 다크·기술·우주적 분위기를 유지하면서도 지식 탐색, 문서 읽기, AI 근거 확인이 빠르고 명확하도록 화면 규칙을 표준화한다.

디자인 우선순위:

1. 읽기와 근거 확인
2. 탐색 경로와 선택 상태의 명확성
3. 빠른 자료 추가와 검색
4. 일관된 상호작용
5. 기술적이고 몰입감 있는 시각 표현

## 1. 브랜드 경험

### 1.1 핵심 인상

- 개인 지식 관제실
- 어두운 우주 공간 위에 떠 있는 연결된 지식
- 차분하지만 살아 있는 탐색 경험
- AI의 판단보다 원문과 출처가 중심인 도구

### 1.2 피해야 할 인상

- 게임 HUD처럼 조작 요소가 과도하게 많은 화면
- 네온 색상만 강조되어 읽기 어려운 화면
- AI 답변이 원문보다 권위 있어 보이는 화면
- 그래프가 움직여서 선택·읽기·검색을 방해하는 화면

## 2. 디자인 토큰

## 3. 타이포그래피

### 3.1 원칙

- 본문과 조작 가능한 텍스트는 최소 text-sm 이상으로 한다.
- 제목은 짧고 강하게, 본문은 충분한 줄 간격으로 표시한다.
- 기술 용어·파일명·노드명은 과도하게 축약하지 않는다.
- 한글과 영문이 섞여도 줄 높이가 무너지지 않는 폰트를 사용한다.

### 3.2 단계

| 스타일 | 크기 | 굵기 | 줄 높이 | 용도 |
|---|---:|---:|---:|---|
| display | 32px | 700 | 1.2 | 빈 상태·주요 메시지 |
| heading-lg | 24px | 700 | 1.3 | 화면 제목 |
| heading-md | 18px | 650 | 1.35 | 패널 제목 |
| body-lg | 16px | 400 | 1.65 | 문서 본문·답변 |
| body | 14px | 400 | 1.55 | 기본 UI 텍스트 |
| label | 12px | 600 | 1.4 | 유형·상태·보조 라벨 |
| mono | 13px | 400 | 1.5 | ID·파일명·기술 값 |

문서 원문과 AI 답변은 body-lg를 기본으로 한다. 입력 placeholder와 비활성 텍스트도 text-sm 미만으로 내리지 않는다.

## 4. 레이아웃

### 4.1 데스크톱 기본

전체 화면은 다음 세 영역을 기본으로 한다.

- topbar: 서비스명, 검색·질문 입력, 자료 추가, 설정
- graph-stage: 3D 그래프와 그래프 도구
- detail-drawer: 선택 노드·문서·답변 근거 패널

detail-drawer는 기본적으로 닫혀 있고, 대상 선택 시 오른쪽에 열린다. 패널이 열려도 그래프는 최소한의 탐색 영역을 유지한다.

### 4.2 최소 화면 너비

- 1280px 이상: 그래프와 상세 패널 동시 사용
- 900~1279px: 상세 패널을 넓은 overlay drawer로 전환
- 600~899px: 그래프 높이를 줄이고 상세 패널을 full-height drawer로 전환
- 599px 이하: 그래프·검색·상세를 순차 화면으로 전환

모바일은 초기 우선순위가 낮지만 핵심 데이터에 접근할 수 없게 만들지는 않는다.

### 4.3 레이어 순서

1. canvas background
2. graph
3. graph controls
4. topbar
5. detail drawer
6. modal backdrop
7. modal
8. toast·critical alert

## 5. 공통 컴포넌트

### 5.1 Button

종류:

- primary: 자료 추가, 질문 실행, 저장 확정
- secondary: 검색, 그래프 보기, 문서 열기
- ghost: 필터·보조 이동
- danger: 삭제·전체 삭제

상태:

- default, hover, focus, pressed, disabled, loading

loading 상태에서는 중복 클릭을 막고 버튼 안에 짧은 진행 문구를 보여준다.

### 5.2 SearchBox

- 검색과 질문을 하나의 진입점으로 제공
- 검색 실행 아이콘과 질문 실행 보조 액션을 구분
- 입력 지우기 제공
- 1,000자 검색, 2,000자 질문 제한을 안내
- 입력 오류를 field 아래에 표시

### 5.3 StatusBadge

상태 텍스트를 아이콘과 색상으로 함께 표시한다.

| 상태 | 문구 예 | 색상 |
|---|---|---|
| queued | 대기 중 | text-secondary |
| analyzing | 분석 중 | accent-violet |
| review_ready | 검토 필요 | accent-amber |
| storing | 저장 중 | accent-cyan |
| ready | 준비됨 | success |
| failed | 실패 | danger |
| deleted | 삭제됨 | text-muted |

### 5.4 NodeTypeBadge

문서, 청크, 개념 유형을 텍스트와 형태로 표시한다. 그래프 색상과 동일한 토큰을 사용한다.

### 5.5 Card

카드에는 한 가지 주제만 담는다. 제목·핵심 정보·주요 액션 순서로 구성하고 보조 메타데이터는 하단에 둔다.

### 5.6 Drawer

- 선택 대상의 제목과 유형을 상단에 표시
- 닫기·뒤로 가기·원문 열기 액션 제공
- 긴 내용은 패널 내부에서 독립적으로 스크롤
- 그래프 선택 상태와 패널 콘텐츠를 항상 일치시킴

### 5.7 Modal

- 모달 진입 시 제목과 현재 단계를 표시
- 입력·분석·검토·완료를 같은 모달 흐름으로 유지
- ESC와 닫기 버튼 동작을 일관되게 제공
- 분석 중 닫기 시 작업 계속 여부를 명시
- 모달 내부 포커스 순환

### 5.8 Toast

성공·경고·실패의 짧은 피드백에만 사용한다. 중요한 오류는 toast만 사용하지 않고 화면의 오류 영역에도 남긴다.

### 5.9 EmptyState

항상 다음을 포함한다.

- 현재 상태 설명
- 사용자가 할 수 있는 다음 행동
- 주요 행동 버튼
- 필요하면 짧은 예시

### 5.10 LoadingState

단순 spinner만 사용하지 않는다. 분석·검색·답변은 단계 문구와 예상되는 다음 상태를 함께 표시한다.

## 6. 화면별 UI 규칙

### 6.1 지식 홈

- 검색창과 자료 추가를 첫 시선 영역에 둔다.
- 그래프는 화면의 주 콘텐츠지만 선택 패널보다 낮은 정보 우선순위를 갖지 않게 한다.
- 노드 수·문서 수·개념 수는 작게 요약한다.
- 그래프에 자료가 없으면 EmptyState를 렌더링한다.

### 6.2 자료 추가 모달

단계 표시:

1. 입력
2. 분석
3. 검토
4. 저장 완료

분석 결과는 원문과 분리된 패널 또는 접을 수 있는 섹션으로 보여준다. 개념과 관계는 각각 제외 액션을 제공한다.

### 6.3 그래프 상세 패널

상단에는 선택된 노드의 대표명과 유형을 둔다. 그 아래에 요약, 근거, 관련 자료, 이동 액션 순으로 배치한다. 개념 설명보다 해당 개념이 등장한 원문과 문서 링크를 우선한다.

- 닫기 버튼은 패널 우측 상단에 고정한다.
- 패널은 배경보다 명확한 테두리와 그림자를 사용하고, 닫기 버튼은 최소 38px hit area와 focus ring을 가진다.
- 패널 외부 영역은 투명 또는 저명도 backdrop으로 덮고 클릭 시 패널을 닫는다.
- 패널 내부 클릭은 닫기 동작을 발생시키지 않는다.
- 선택 노드는 패널을 닫은 뒤에도 그래프에서 강조 상태를 유지한다. 그래프 도구의 `노드 정보` 버튼으로 패널을 다시 열 수 있으며, 선택 노드가 없으면 버튼을 비활성화한다.
- 선택 노드 상세에는 `RELATION EDGES` 블록을 두고 대상 노드·관계명·관계 유형·신뢰도·근거 발췌를 카드 단위로 표시한다. 대상 카드는 관련 노드 탐색 액션을 제공한다.

### 6.4 검색 결과

결과마다 순위·제목·발췌·관련도·결과 유형을 보여준다. 검색 결과에서 문서 열기와 그래프 보기 액션은 같은 수준으로 제공한다.

### 6.5 질문 답변

답변과 근거를 시각적으로 분리한다.

- answer card: AI 답변
- evidence cards: 근거 청크 최대 3개
- related concept strip: 추가 그래프 탐색
- status banner: 근거 충분·부족·실패

근거 번호는 답변의 주장과 evidence card를 연결한다. 근거가 없는 답변 문장은 근거 번호를 만들지 않는다.

### 6.6 히스토리

질문 목록은 질문 원문을 우선 노출한다. 답변 미리보기는 보조로 사용한다. 삭제된 문서가 포함된 과거 결과는 회색 상태로 표시한다.

## 7. 그래프 시각화 규칙

### 7.1 노드

- 문서: 가장 큰 기본 노드, 사각형 계열
- 개념: 원형, 유형별 색상
- 청크: 작은 둥근 사각형, 기본 숨김
- 새로 생성된 노드: 일정 시간 glow
- 선택 노드: 밝은 외곽선과 주변 연결 강조
- 검색 일치 노드: cyan ring

노드 크기는 연결 수와 의미를 단순히 동일시하지 않는다. 초기에는 문서·개념·청크의 역할을 우선하고, 연결 수는 보조 크기 차이로만 사용한다.

### 7.2 엣지

- 일반 관계: 얇은 반투명 선
- 선택 경로: 밝고 두꺼운 선
- 근거 관계: amber 또는 선택 상태 색상
- 방향성이 중요한 관계는 화살표 또는 방향 표시
- 겹치는 엣지는 선택 시에만 라벨 표시

### 7.3 카메라와 상호작용

- 첫 진입 시 전체 그래프를 안정적으로 맞춘다.
- 노드 선택 시 부드럽게 중심 이동하되 자동 회전은 멈춘다.
- 사용자가 직접 회전한 뒤 자동 위치 재설정을 강제하지 않는다.
- 전체 보기 버튼으로 초기 카메라 상태를 복원한다.
- focus 노드와 depth 필터를 사용하면 주변 맥락만 강조한다.
- `선택 노드 정렬` 실행 시 focus 노드를 0-hop 중심 열에 두고 최단 홉 수별 노드를 같은 열의 행으로 배치한다. 관계선은 좌우 열 사이를 직선적으로 읽을 수 있어야 한다.
- 클러스터 확대·축소는 `− / +` 컨트롤과 마우스 휠을 모두 지원하며 현재 배율을 표시한다.

### 7.4 3D 공간과 클러스터 정렬

- 모든 노드는 x·y·z 좌표를 가진 3D 공간에 배치하고, 깊이에 따른 원근과 연결선으로 관계를 표현한다.
- 정렬 상태에서 focus 노드는 중심 좌표에 두고, 1-hop·2-hop 이상의 연결 노드는 홉 수별 x 열에 배치한다. 같은 홉의 노드는 y 행으로 분산하고 z 깊이는 최소화해 관계성을 평면적으로 읽게 한다.
- focus 범위를 확대할 때는 focus 노드에서 연결 가능한 모든 노드를 홉 수별로 포함하되, 카메라 fit은 전체 정렬 범위를 화면에 맞춘다.
- 전체 보기에서는 전체 그래프를 다시 맞추며, focus 해제와 배율을 기본값으로 되돌린다.
- 위치와 배율은 현재 화면 세션의 UI 상태이며 문서·관계 데이터로 저장하지 않는다.
- 정렬 시 직접 연결이 없는 노드와 별도 연결 컴포넌트도 전체 카메라 범위에 포함해, 노드·엣지가 화면 밖으로 사라진 것처럼 보이지 않게 한다.

### 7.5 노드 드래그

- 포인터를 노드에 누른 채 이동하면 개별 노드의 위치를 현재 화면에서 조정한다.
- 드래그 중에는 노드가 `grabbing` 상태로 보이고, 연결선은 새 노드 위치를 즉시 따라간다.
- 짧은 클릭과 드래그를 구분한다. 드래그 직후에는 오작동으로 상세 패널이 열리지 않아야 한다.
- 드래그한 위치는 문서 데이터가 아닌 그래프 UI 상태로 취급하며, 초기에는 서버·브라우저 저장을 하지 않는다.
- 전체 보기 또는 그래프 데이터 초기화 시 기본 배치로 복원한다.
- 노드 이동 후에도 노드의 상세 보기, 검색 결과 강조, 관련 노드 이동은 동일한 엔터티를 대상으로 동작한다.

## 8. 모션

| 상황 | 모션 | 제한 |
|---|---|---|
| 새 노드 추가 | fade + 짧은 scale | 500ms 이하 |
| 패널 열기 | slide | 250ms 이하 |
| 검색 강조 | glow pulse | 2회 이하 |
| 분석 진행 | 단계 전환 | 반복 깜박임 금지 |
| 성공 | 짧은 highlight | 800ms 이하 |

사용자가 reduced motion을 설정하면 관계선 입자 애니메이션만 제거하고, 노드·관계선·선택 강조는 유지한다.

## 9. 접근성

- 모든 버튼과 입력은 키보드로 접근한다.
- focus ring은 배경에서 명확히 보여야 한다.
- 모달 안으로 포커스를 이동하고 닫을 때 원래 트리거로 되돌린다.
- 그래프 정보는 선택 패널·목록·검색 결과로도 접근한다.
- 상태는 색상과 텍스트를 함께 사용한다.
- 오류 메시지는 오류가 발생한 입력 근처에 표시한다.
- 긴 원문은 heading 구조와 읽기 가능한 줄 길이를 사용한다.
- 애니메이션 최소화 설정을 존중한다.

## 10. 콘텐츠 문체

- 버튼: 동사 중심. 예: 자료 추가, 분석 시작, 저장하기
- 상태: 현재 진행을 설명. 예: 개념을 찾는 중
- 오류: 원인과 다음 행동을 함께 표시
- AI 한계: “저장된 자료에서 충분한 근거를 찾지 못했습니다.”
- 추출 불확실성: “확인 후보” 또는 “자동 추출 후보”
- 문서 발췌는 원문의 문체를 보존하고 임의로 의미를 바꾸지 않는다.

## 11. 화면 상태 매트릭스

| 화면 | 기본 | 빈 상태 | 로딩 | 성공 | 실패 |
|---|---|---|---|---|---|
| 홈 | 그래프 | 첫 자료 안내 | 그래프 갱신 | 새 노드 강조 | 갱신 실패 배너 |
| 추가 모달 | 입력 | 입력 안내 | 단계 진행 | 검토 화면 | 재시도·원문 저장 |
| 검색 | 최근 결과 | 검색 안내 | 결과 skeleton | 결과 카드 | 검색어 수정 안내 |
| 질문 | 입력 | 질문 안내 | 검색 중·답변 중 | 답변+근거 | 재시도·근거 부족 |
| 히스토리 | 목록 | 기록 없음 | 목록 로딩 | 상세 재열람 | 기록 로딩 실패 |

## 12. 디자인 검수 기준

- 첫 화면에서 자료 추가와 검색을 3초 안에 발견할 수 있는가
- 선택된 노드와 열린 상세 패널이 일치하는가
- 문서·청크·개념의 차이를 색상 없이도 알 수 있는가
- 답변과 근거 청크가 분리되어 보이는가
- 모든 로딩·실패·빈 상태에 다음 행동이 있는가
- 최소 text-sm 규칙을 위반한 핵심 UI가 없는가
- 그래프의 움직임이 읽기와 선택을 방해하지 않는가
- 키보드와 reduced motion 사용자가 핵심 기능을 수행할 수 있는가

### 6.6 멀티턴 질문 화면

- 질문 화면은 `conversation transcript`를 세로로 쌓고, 사용자 질문과 AI 답변의 시각적 역할을 명확히 구분한다.
- 각 답변 바로 아래에 해당 턴의 근거 청크를 최대 3개 표시한다. 근거가 없는 턴은 링크 영역 대신 근거 부족 상태를 표시한다.
- 입력 영역에는 `새 대화`와 `질문 보내기`를 함께 제공한다. 전송 중에는 중복 전송을 막고 진행 상태를 표시한다.
- 대화 제목은 첫 질문을 축약해 표시하고, 히스토리 목록에는 턴 수와 마지막 활동 시각을 함께 표시한다.
- 대화 상세를 열면 전체 턴을 복원하며, 각 턴의 문서 링크와 그래프 이동 액션을 유지한다.
- 모델 오류·네트워크 오류·근거 부족은 서로 다른 상태 색상과 설명을 사용하되, 색상만으로 의미를 전달하지 않는다.
- 긴 대화는 transcript 내부만 스크롤하고 질문 입력은 고정한다. `text-sm` 미만의 핵심 텍스트는 사용하지 않는다.
- EvidenceCard를 선택하면 문서 drawer의 `근거 위치 매칭` 블록에 청크 순번·원문 offset·발췌를 표시한다. 원문은 amber highlight, 청크 목록은 active border로 동일 대상을 표시한다.

### 7.7 Agent 활동 상태

- 질문 제출 직후 `queued`, `running`, `도구 실행 중`, `completed`, `failed`, `max_turns`, `cancelled`를 구분해 표시한다.
- 활동 timeline 문구는 서버가 만든 짧은 UI-safe 문구를 사용한다: `지식 검색 중: '…'`, `노드 탐색 중: '…'`, `웹 검색 중: '…'`.
- 도구 입력·출력 JSON과 내부 reasoning은 기본 숨김이며, 결과 개수·출처 수·오류·재시도 여부만 표시한다.
- local evidence는 기존 amber 원문 매칭, web source는 별도 색상·외부 링크로 구분한다. 색상만으로 상태를 전달하지 않는다.
- SSE 연결이 끊기면 재연결 또는 polling 상태를 제공하고, 최종 결과가 늦어져도 정지한 화면처럼 보이지 않게 한다.
### 그래프 stage 확장과 연속 등록

- 데스크톱에서는 graph-stage를 본문 가로 전체에 배치하고 보조 자료 목록은 아래에 둔다.
- 자료 추가 완료 후 `다음 자료 추가` secondary action으로 현재 모달을 유지한다.
- 다음 등록을 위해 입력 초안만 초기화하고 이미 저장된 그래프·목록 상태는 유지한다.

### 자료 업로드 및 그래프 상태 문구

- 파일 영역은 `여러 PDF, TXT, MD 파일을 한 번에 선택하거나 끌어놓으세요`를 기본 안내로 사용한다.
- 다중 선택 시 버튼은 `N개 자료 분석 시작`으로 표시하고, 현재 파일과 남은 대기 파일을 구분한다.
- 분석 실패는 입력 단계에 오류 테두리와 `role=alert` 메시지를 표시한다.
- 그래프 도구 이름은 축약어 대신 `선택 노드 정렬`, `전체 그래프`, `청크 포함/숨기기`, `모션 끄기/켜기`를 사용한다.
- 노드 반경은 문서 > 개념 > 청크 순으로 구분하되, 기본 노드가 배경에 묻히지 않도록 최소 크기를 보장한다. 선택만으로 카메라 위치를 변경하지 않는다.
### 7.6 그래프 라벨

- 노드 대표명은 3D 노드 옆의 고정 라벨로 항상 표시한다. 문서·개념·청크 라벨은 유형 색상과 대비되는 텍스트 및 반투명 배경을 사용한다.
- 엣지 관계명은 엣지 중간에 고정 표시한다. 값은 `label`을 우선하고 없으면 `relation_type`을 표시한다.
- 관계명 라벨은 작은 보조 텍스트로 표현하되 배경·외곽선을 적용해 연결선 위에서도 읽혀야 한다.
- 긴 노드명·관계명은 그래프 밀도를 제어하기 위해 말줄임하며, 전체 값은 hover tooltip과 상세 패널에서 제공한다.
- fallback 그래프도 동일한 노드명·관계명 정보를 SVG 텍스트로 제공한다.
## 작업공간 내비게이션 및 외부 출처 카드

- 좌측 내비게이션 순서: `✦ 지식 유니버스` → `▤ 자료 라이브러리` → `◉ AI 대화` → `◷ 검색 이력`.
- 아이콘은 장식이 아니라 탭 의미를 보강하는 보조 정보이며, 텍스트·`title`·접근성 이름을 함께 제공한다.
- 활성 탭은 좌측 강조선, 높은 명도, 배경 대비로 표시한다. 축소 화면에서는 아이콘을 유지하고 툴팁을 제공한다.
- AI 대화의 외부 출처는 제목, 도메인/URL, 짧은 발췌, `원문 열기`, `자료로 저장` 액션을 갖는 카드로 표시한다. 외부 링크는 새 탭으로 연다.
- `자료로 저장`은 사용자의 명시적 클릭 후에만 실행하며 저장 중 상태와 실패 사유를 같은 카드에 표시한다.
- 그래프 노드 라벨은 일반 개념 64px, 원본 72px, 관계 56px의 캔버스 텍스처 기준으로 생성해 3D 거리에서도 읽히게 하고 선택 상태에서 테두리·명도를 높인다.
